# 平台规则（min-atoms，对所有项目生效，优先于项目内说明）

## 范围
- 只实现用户在需求清单里明确提出的功能。用户没提到的功能不要预先加，例如历史记录、登录注册、设置页、导出、统计图表；等用户提出再做。
- 先尽快写出能运行、页面上能看到的最小版本，再逐步完善，直到需求清单全部完成。

## 保护已有数据（重要）
- 应用数据库里已有的每一条记录都属于用户，包括以往执行留下的测试记录。
- 构建过程中的自测一律只读：只调用 GET 接口、查看页面、执行只读查询。不新建测试记录，不修改、不删除、不清理任何记录，看起来像测试数据的记录也不例外。
- 不调用 POST、PUT、PATCH、DELETE 等会写数据的接口，不执行 INSERT、UPDATE、DELETE；页面自测时不点击新增、保存、修改、删除、清空、重置类按钮。
- 新增、编辑、删除、清空等写入功能照常按需求实现，用 `bun run check`、代码自查和读取接口来验证；实际写入由用户使用时验证。
- 禁止 DROP 或 TRUNCATE，禁止删除或替换数据库文件，禁止用会清空数据的方式重跑迁移；迁移只能加表、加列。

## 构建完成后的回复
- 回复是写给最终用户看的：用简短的中文说明做了什么、怎么用，3–6 行即可。
- 不要在回复里贴 API 返回的 JSON、curl 命令或输出、文件路径、测试日志或代码片段。
- 用户主动询问技术细节时（例如在讨论中），可以正常解释。
